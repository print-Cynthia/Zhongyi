# 组织架构（org.md）

> 稳定层。定义主管、6 部门、PM 与验收闭环。跨项目复用。

## 1. 主管（Master）
见 [roles/master.md](roles/master.md)。一句话：本项目总负责人，等价于"一人公司"的老板 / 项目组负责人，负责派活、跨部门协调、验收闭环与异常处理。

## 2. 六个部门与边界
| 部门 | 性质 | 核心职责 | 下属 AI 员工数 |
|---|---|---|---|
| 设计组 | 稳定 | 视觉规范落地、组件库、交互原型 | 3 |
| 工程组 | 稳定 | 全部代码实现（含 4 道工序：采集 / 辨证 / 报告 / 安全） | 4 |
| 体验组 | 稳定 | 流程测试、可用性、语气把关 | 3 |
| 质量组 | 稳定 | 自动预检、回归、边界检查 | 3 |
| 中医组 | 领域 | 医学准确性审核（辨证 / 本草 / 文献） | 3 |
| 合规组 | 领域 | 免责 / 无诊断 / 无处方 / 隐私 | 3 |

> 部门数量可扩展（未来可加 数据组 / 运营组 / 增长组 等），但当前项目以这 6 个为最小起步集。扩展时只在 `roles/` 与 `staff/` 增加对应文件，稳定层骨架不变。

## 3. PM 定位
PM = **部门内的管理者**，不是浮在部门之上的独立层。职责：
- 把关本部门所有产出（对照 PRD 需求 + 验收清单）；
- 拥有**打回权**（不达标打回重写，理由写入验收意见）；
- 向主管汇报本部门状态；跨 PM 协同接口见各部门文件。

6 名 PM：`design` / `engineering` / `experience` / `quality` / `tcm` / `compliance`（见 `roles/pm-*.md`）。

## 4. 汇报关系
```
用户（终审法官）
   │ 审批闸
   ▼
主管 Master
   │ 派活 / 协调
   ▼
6 部门（每组 1 PM + N AI 员工）
   │ 产出草稿
   ▼
质量组自动预检 ──► 用户人工终审 ──► 放行 / 打回
```

## 5. 验收闭环
1. 主管据 PRD + 任务单派活给各部门。
2. 各部门 AI 员工产出草稿，PM 内部把关。
3. **质量组自动预检**（对照 `acceptance/auto-checklist.md`）→ 生成预检报告。
4. **用户人工终审**（`acceptance/human-review.md`）→ 放行或打回。
5. 打回项回到对应部门修订，回到第 3 步；全绿后放行，进入下一轮（代码实现）。

## 6. 稳定层 vs 可换层（迁移边界）
- **稳定层（原样带走）**：`org.md`、`roles/`、`acceptance/`、`style-guide.md`。
- **可换层（迁移替换）**：`staff/`（AI 员工）、`domain/`（领域组）。
- 设计原则：上层（主管 / 部门 / PM）定义"组织怎么运转"，下层（AI 员工）定义"谁具体干、怎么干"。换项目只换下层，上层复用。
